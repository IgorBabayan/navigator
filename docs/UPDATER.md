# Automatic updater

`src/Navigator.Updater` (BCL only) + `src/Navigator.Presentation/Updates/UpdateViewModel.cs`.
The design is adapted from ED Assistant's updater (see `docs/SOURCE_ORIGINALITY.md`) and hardened.

## Flow

```
startup (after first frame) ─► cleanup of the previous update ─► check (startup + every N hours)
   └─► newer stable release? ─► download asset (resumable) ─► verify size + SHA-256 ─► prepare installer
        └─► "Restart to update" ─► file operations running? ── yes ─► wait until the queue is idle
                                                          └─ no ──► start installer/swap script, exit
```

## Release discovery (`GitHubReleaseSource`)

- `GET https://api.github.com/repos/{owner}/{repo}/releases?per_page=20`; drafts are ignored, prereleases
  only on the Prerelease channel.
- Each candidate must contain `update-manifest.json`; the manifest's `version` must equal the tag.
- When the app was built with `NAVIGATOR_UPDATE_PUBLIC_KEY`, `update-manifest.json.sig` (ECDSA P-256,
  SHA-256) is **required** and verified before the manifest is trusted. Unsigned or tampered manifests
  are rejected.
- Only versions strictly greater than the running version are offered (never downgrade). A version the user
  chose to skip is not offered again automatically.

## Manifest (`update-manifest.json`)

```json
{
  "schemaVersion": 1,
  "product": "Navigator",
  "version": "1.2.3",
  "channel": "stable",
  "commit": "<40-hex merge commit>",
  "publishedAt": "2026-11-24T10:00:00+00:00",
  "releaseNotes": "…",
  "assets": [
    { "name": "Navigator-1.2.3-win-x64-setup.exe", "rid": "win-x64", "kind": "installer",
      "size": 51234567, "sha256": "…64 hex…" }
  ]
}
```
Asset kinds: `installer` (Windows Inno Setup), `portable` (Windows zip / Linux tar.gz), `appimage`,
`app-archive` (macOS zip of `Navigator.app`), `dmg` (manual installs only). `UpdateManifest.Parse` rejects
missing fields, invalid hashes, path separators in names and duplicate rid/kind pairs.

## Installation kinds and how each is updated

| Kind (`InstallationDetector`) | Detected by | Update strategy |
|---|---|---|
| `WindowsInstaller` | `unins000.exe` (Inno uninstaller) next to the executable | run the new `-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART` after exit; relaunch |
| `WindowsPortable` | `.navigator-portable` marker next to the executable | extract to a staging folder; PowerShell script waits for exit, renames current folder to backup, moves staging in, relaunches; restores backup on failure |
| `LinuxAppImage` | `APPIMAGE` environment variable | download next to the AppImage, mark executable, rename current to `.old`, rename new into place, relaunch; `.old` removed after a successful start |
| `LinuxPortable` | `.navigator-portable` marker (tar.gz layout) | same staging/backup swap as Windows portable with a `sh` script |
| `LinuxPackageManaged` | installed under `/usr/` or `/opt/` without the portable marker | notify only — the package manager owns the files |
| `MacAppBundle` | running from a writable `Navigator.app` | `ditto` extract, `codesign --verify`, swap bundle with backup, relaunch |
| `MacAppBundleReadOnly` | bundle not writable (e.g. `/Applications` without admin) | notify with a link (manual update) |
| `Development` | anything else, or no update repository compiled in | updater disabled |

The swap scripts are generated by `DirectorySwapUpdate` (paths validated by `SafeTarget`, quoted, no user
input). The previous version is kept until the new one has started once (`CleanupAfterSuccessfulStart`).

## Download (`UpdateDownloader`)

HTTPS only; `Range` resume of `*.partial` files; up to 4 attempts with backoff; size check, then SHA-256
check; a corrupt file is deleted. Downloads go to the app cache `updates` folder.

## Safety rules

- Never restart while file operations are queued or running: the view model enters
  `WaitingForOperations` and retries when the queue becomes idle.
- Never install an asset whose hash differs from the (signed) manifest.
- Never downgrade; never act on drafts.
- Failures leave the current installation untouched and are shown in Settings → Updates and in the log.

## Settings

Settings → Updates: check on startup (default on), check interval in hours (default 24, 0 = off), channel
(Stable / Prerelease), "Check now", skipped version.

## Configuration at build time

`dotnet publish … -p:UpdateRepository=owner/repo -p:UpdatePublicKey=<base64 SPKI>` writes
`AssemblyMetadata("UpdateRepository")` / `("UpdatePublicKey")`, read by `UpdateConfiguration.FromAssembly`.
Local builds have neither, so the updater stays disabled.

## Validation status

Manifest parsing, signatures, asset selection, release selection, downloader (hash + resume), installation
detection and swap-path safety are unit-tested. Running a real swap/installer on each OS has **not** been
done yet (`docs/KNOWN_ISSUES.md`).
