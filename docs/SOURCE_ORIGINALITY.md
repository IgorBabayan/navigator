# Source originality

## Policy

Navigator reproduces the *experience* of the Files app (https://files.community): its layout, visual
language, interactions, animations and feature set. It does **not** reuse Files app source code.

- Files app code, XAML, styles, resources, assets, tests, architecture and project structure were not
  opened, copied, translated, paraphrased or adapted while writing Navigator.
- Behavior was derived from the running application, the public website/documentation and screenshots.
- Converting WinUI/XAML to Avalonia/AXAML, renaming identifiers or reformatting would still be copying and
  is not allowed.
- Contributors must follow the same rule (see `CONTRIBUTING.md`).

## Reused code from ED Assistant

ED Assistant (https://github.com/IgorBabayan/ed-assistant) is by the same author and is explicitly allowed
as a source. The following parts were **adapted** (design and approach; code rewritten for Navigator):

| Navigator component | ED Assistant origin | Notes |
|---|---|---|
| `src/Navigator.Updater/*` | Its GitHub Releases updater | Same overall flow (release query → asset selection → verified download → installer per installation type → restart). Added: signed manifest, resumable download, never-restart-during-operations, rollback swap scripts. |
| `.github/workflows/release.yml` | Its release workflow | Structure of the per-platform build matrix and draft → publish flow. Added: atomic tag-based version reservation, retry-safe reuse, uploaded-asset verification, Latest reconciliation. |
| `installer/windows/Navigator.iss` | Its Inno Setup script | Structure only; ids, names, paths and options are Navigator's. |
| `installer/linux/package.sh`, `installer/macos/package.sh` | Its AppImage and .app packaging steps | Approach (AppDir + appimagetool; ditto ZIP + hdiutil DMG). |

## Verification

Automated: `tools/originality/similarity_scan.py` hashes every window of 8 consecutive significant,
whitespace-normalized lines of the reference repository and reports identical windows in Navigator's
sources. The reference code is hashed only, never displayed.

Result recorded on 2026-11-24 against a shallow clone of `files-community/Files` (default branch):

| Scope | Windows scanned | Exact matches | Literal-masked matches |
|---|---|---|---|
| `src/` (121 files) | 10,073 | **0** | 4 — all false positives: runs of 8 generic `<SolidColorBrush x:Key=… Color=…/>` / `<Setter Property=… Value=…/>` lines whose keys/values differ |
| `tests/` (8 files) | 1,289 | **0** | not run |

Re-run on 2026-11-25 for the type-aware item context menu (designed from screenshots of the running app only):
`src/` 184 files, 17,571 windows, **0** exact matches; literal-masked matches unchanged from before the change (all
pre-existing token/style runs). Additionally every non-trivial line the change adds (660 lines of 30+ characters) was
compared one by one with the reference: the only identical lines are three `using` directives.

Re-run later on 2026-11-25 after the Files-style context menus and Material icons: `src/` 189 files, 18,309 windows,
**0** exact matches (tests: 0); literal-masked matches unchanged (25, all pre-existing token/style runs, none in the
new files). Of 1,702 added lines of 20+ characters, 14 equal a line of the reference — all language boilerplate that
has a single spelling (`using` directives, `[StructLayout(LayoutKind.Sequential)]`, `[return: MarshalAs(...)]`,
`catch (OperationCanceledException)`, `public void Dispose()`, an auto-property declaration).

The reference clone was deleted after the scan. Re-run before every release:

```bash
git clone --depth 1 https://github.com/files-community/Files.git /tmp/files-ref
python3 tools/originality/similarity_scan.py /tmp/files-ref src
python3 tools/originality/similarity_scan.py /tmp/files-ref src --mask-literals   # review every hit
rm -rf /tmp/files-ref
```

Manual: reviewers check new views and services were written from behavior descriptions, not from source.
